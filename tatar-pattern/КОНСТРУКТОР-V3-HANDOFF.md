# Конструктор v3 — что сделано и что делать дальше

Дата: 30.10.2026. Автор: Claude (Чат 10). Для: владельца проекта, beget-агента, агента отчётности.

## 1. Коротко
Параметрический режим сайта заменён на **конструктор v3**. Это 6 традиционных каркасов (Букет, Розетка, Кайма-лоза, Полотенце, Платок, Бесшовный узор), стебли, зеркальная симметрия, 8 палитр, все 110 мотивов в любой композиции. Ошибок «не поддерживается» больше нет. Интерфейс перенесён из Figma (`html дизайнов/v3`), с анимациями и mesh-gradient на кнопке генерации.

Всё проверено **локально**. Облако (Beget, immers.cloud) не трогали.

## 2. Что изменилось в коде

### Backend (`tatar-pattern/backend/app`)
| Файл | Что |
|---|---|
| `v3/core.py, compositions.py, frames.py, engine.py` | Генератор v3 (перенесён из `prototype-v3/`). Мотивы читает **только из принятого каталога** (`approved_element_files`), спрайты строит в памяти. |
| `v3/elements.json` | Разметка 110 элементов: категории (цветы, листья…) и техника-источник. Создаётся `prototype-v3/build_cache.py`. |
| `v3/service.py` | Каталог для интерфейса, превью, быстрые варианты, сохранение полноразмерного файла. |
| `models.py` | `V3Params`, `V3Variants`; в `Selections` добавлены `renderer='composition-v3'` и поле `v3`. |
| `main.py` | Новые маршруты (см. ниже); `composition-v3` в `/generations` и guest preflight; кэш картинок v3 на сутки. |

**Новые маршруты API:**
- `GET /api/v3/catalog` — композиции, палитры, фоны, форматы, мотивы.
- `POST /api/v3/variants` `{params, seeds[1..4]}` — 4 превью-варианта (800 px, ~1–3 с), **ничего не сохраняет**. Лимит: 40 запросов в минуту с одного IP.
- `GET /api/v3/previews/{comp-*|den-*-*|pal-*-*}.jpg` — картинки для окон выбора (кэш в памяти процесса).
- `GET /api/v3/thumbs/TP-E-xxx.png` — миниатюры мотивов.
- Сохранение и экспорт идут прежним гостевым путём: `POST /api/guest/preflight` → `/api/guest/generations` с `selections.renderer="composition-v3"` → `/file?format=png|jpg`, для бесшовного узора ещё `artifact=module`.

Старые генераторы (legacy, v1, v2) и ИИ-маршруты **не удалены** и работают как раньше.

### Анимации
- Плитки появляются каскадом.
- Выбранное значение «проявляется» на плитке.
- Карточки карусели морфятся при перелистывании.
- Галочка «Выбрано» дорисовывается.
- Кнопка генерации растягивается в mesh-gradient, 4 светящиеся точки крутятся и пульсируют как загрузка.
- Результат появляется плавно; кубик крутится, пока собираются новые варианты.
- Если в системе включено «уменьшение движения», анимации выключаются.

## 4. Выпуск на Beget (для владельца и beget-агента)
1. Собрать новый выпуск тем же способом, что и прежний (`deploy/`: `package_release.py` / `ops.py build`, платформа `linux/amd64`). В образ backend `app/v3/` попадает автоматически (`Dockerfile.backend` копирует `backend/app`). Новых зависимостей нет: только Pillow, он уже есть.
2. **Миграции и каталог не меняются.** v3 использует тот же принятый каталог из 110 элементов.
3. После запуска проверить:
   - `curl https://tatar-pattern.ru/api/v3/catalog` → 6 композиций и 110 мотивов;
   - `python3 backend/local-test/v3-smoke.py https://tatar-pattern.ru` → «итог: 6/6». Скрипт создаёт 6 гостевых работ, они удаляются по сроку гостя.
4. Если у Caddy или прокси есть белый список путей `/api/...` — добавить `/api/v3/`.
5. Ресурсы: один набор вариантов — около 1–3 секунд CPU. Одновременно работают не больше 2 рендеров (`render_slots`), лишние ждут до 30 секунд, потом получают ответ «Генератор занят».
6. Откат: вернуть предыдущие образы. Данные v3 в базу не пишутся, кроме обычных гостевых работ.

## 5. Что сделать с ИИ-режимом (рекомендация)
Сроков на перекалибровку (ControlNet) нет, поэтому:
- **На сайте:** оставить ИИ-режим как есть. Он доступен только по отдельному переключателю «ИИ» и сейчас выключен (`AI_MVP_ENABLED=false`, бюджет GPU 0). Пользователь видит понятное сообщение «временно недоступно». Включать для сдачи не нужно.
- **В отчёте Фонду** описать ИИ-часть как выполненный этап НИОКР:
  1. собран датасет и обучена LoRA для SDXL на авторских данных;
  2. развёрнут и проверен GPU-сервис на immers.cloud (1500 ₽ — это аренда для обучения, проверки и тестовых генераций, следы есть в `ИИ/gpu-runtime/`);
  3. эксперимент показал ограничение метода img2img: при силе около 0,55 результат почти совпадает с основой, при 0,76 растёт риск искажения мотивов. Это противоречит цели сохранить семантику;
  4. по итогам эксперимента основным режимом выбран параметрический конструктор v3, а ИИ переведён в экспериментальный режим;
  5. следующий этап — ControlNet: он удерживает контуры мотивов и меняет только материал («показать в вышивке / золотом шитье / керамике»), на вход подаётся композиция из конструктора v3.

  Это честный исследовательский результат, а не отказ от работы.
- **Если Фонд попросит доработку:** ControlNet (SDXL Canny/Lineart) в `ИИ/service/workflow.py`, приём PNG из `/api/v3/variants`, выбор «материала» вместо «графический/фактурный». Это 2–4 дня работы.

## 7. Известные ограничения
- Перекраска палитрами автоматическая. На фотофактурных мотивах (030, 031, 053, 072, 073, 116, 119, 011) она хуже, поэтому автоподбор их не берёт, но вручную выбрать их можно.
- Превью карусели строятся при первом открытии (около 0,2 с на картинку), потом кэшируются на сутки.
- «Недавние генерации» показывают каждый набор вариантов, но только до перезагрузки страницы (память вкладки, на сервер ничего не пишется). Файл на сервере появляется только при экспорте.
- Кнопка «Сгенерировать узор» активна только после выбора Композиции, Насыщенности, Палитры, Фона и Формата (Мотивы необязательны).
- Плашка «1 Insight» в углу на скриншотах — это индикатор режима разработки Next.js. В выпуске её нет.
- Next.js 16.4.0 при запуске `next dev` предупреждает об известной уязвимости и советует обновиться (`next upgrade`). Обновление не делалось. Решение — за beget-агентом при сборке выпуска (раньше уже был отдельный npm audit, см. `deploy/HANDOFF.md`).

```bash
# frontend (в другом окне)
cd tatar-pattern/frontend && API_ORIGIN=http://127.0.0.1:8000 npx next dev -p 3000
# открыть http://localhost:3000/constructor
```
