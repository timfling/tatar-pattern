## 2. Как открыть нынешний закрытый сайт на Mac

1. Открыть приложение «Терминал» на Mac, новую локальную вкладку. В ней выполнить:

```sh
ssh -N -T -i ~/.ssh/tatar_pattern_beget_ed25519 -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -L localhost:18080:127.0.0.1:18080 root@159.194.210.167
```

2. При запросе `Enter passphrase for key ...` ввести парольную фразу ключа в Терминале. Символы не видны. В чат пароль не отправлять. Изменившийся host key не принимать без независимой проверки.
3. Если команда молча остаётся работать — это нормально. Оставить окно открытым. Открыть **Firefox → `https://localhost:18080`**. Firefox использовался успешно 24.10; Safari тогда не подключался. Конкретный текущий браузерный результат ещё не проверен.
4. Сертификат — локальный Caddy CA, а не публичный сертификат домена. Если браузер показывает предупреждение, решение о доверии принимает владелец только для своего localhost после проверки соединения/CA; агент не обходит предупреждение. Наличие прежнего исключения не гарантировано. Не выключать проверку HTTPS во всём браузере.
5. Пользоваться flat-конструктором. Гостевые результаты имеют срок до 24 часов; старые работы могли уже исчезнуть штатно. Нужные PNG/JPG скачать отдельно. Сообщение об AI не означает, что GPU следует включить.
6. Остановить закрытый доступ: вернуться в эту вкладку Терминала, нажать `Ctrl+C`. Сайт на VPS продолжит работать; закрывается только туннель Mac.

`Address already in use` означает занятый локальный 18080: сначала проверить, не работает ли прежняя вкладка туннеля, и попробовать сайт. Не менять порт вслепую: origin/CORS настроен на localhost:18080. При `Permission denied (publickey)` или иной ошибке передать её текст без ключей/секретов.

Отдельная серверная вкладка для проверки обслуживания:

```sh
ssh -i ~/.ssh/tatar_pattern_beget_ed25519 -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes root@159.194.210.167
python3 -B /etc/tatar-pattern/staging-maintenance.py status
systemctl list-timers --all 'tatar-staging-*'
```

Последние две команды — **в серверном приглашении `root@…`**, не на Mac. Ожидаем `HTTPS/catalog110 OK`, worker stopped/absent, `LOCAL MAINTENANCE STATUS PASS`. Ошибка требует разбора; автоматически запускать worker/tunnel нельзя.

## 4. Flat-only: конкретная подготовка и статус

Созданы в deploy, вне sealed:

- `compose.flat-only.yml`: применять **последним** после AI overrides; backend/worker `AI_MVP_ENABLED=false`, budget0, worker restart=no. Это глобальный feature switch плюс дополнительный нулевой бюджет; использованный счётчик2 не обнулять.
- `beget_flat_only_20261025.py`: plan по умолчанию, применение только `--apply`. Принимает точный staging override24.10 и maintenance v2 с SHA; блокируется при работающем worker/tunnel, незавершённых AI, чужой конфигурации/невалидном drain ledger. Сохраняет rollback-конфигурацию, mounts/hotfix/реестры и БД; пересоздаёт **только backend** с `--no-deps`. Не соединяется с GPU/не запускает AI worker. После применения проверяет110/flat=true/AI=false/`AI_DISABLED` всех пар и пишет `checks/flat-only-20261025.json`.

Локальная проверка: 3 safety tests PASS (отказ при чужом mount/бюджете/сервисе; сохранность binds и повторный close; реальный AI-каталог с недоступным GPU не вызывает readiness и отдаёт AI_DISABLED). Python3.9 grammar PASS. Compose config на synthetic env без запуска daemon/сервисов подтвердил false/0 поверх прежнего true/2 и сохранность readonly hotfix. В первой попытке config недоставало synthetic ACME_EMAIL; после заполнения config PASS.

Применение **NOT_RUN**: SSH без ручной парольной фразы недоступен. Последний живой статус остаётся прежним, UI ещё не исправлен. Локальные проверки не заменяют применение на VPS.

При проблеме исправлять/откатывать flat-конфигурацию с сохранением AI=false; worker/tunnel не запускать. Sealed release и прежний bind hotfix остаются доступны для возврата совместимого backend.
