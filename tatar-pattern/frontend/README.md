# TATAR PATTERN — frontend

Next.js 16.3.2 / React 19 / TypeScript. Рабочая папка — `Разработка/tatar-pattern/frontend`.
Локальные правила Next.js находятся в AGENTS.md и поставляемых с установленным
пакетом `node_modules/next/dist/docs/`.

## Запуск

```sh
npm ci
API_ORIGIN=http://127.0.0.1:8000 npm run dev
```

`API_ORIGIN` включает серверный proxy `/api` через Next.js. В браузере API и файлы
остаются на одном origin, используется HttpOnly cookie. Пример настроек —
`.env.example`. Адрес API должен указывать на уже настроенный backend;
frontend не выполняет миграции и не наполняет каталог.

При раздельных origin можно задать `NEXT_PUBLIC_API_ORIGIN` (только origin,
без `/api`). Это build-time переменная; backend должен разрешать точный origin
frontend в CORS. Предпочтителен единый публичный origin с proxy `/api`.

## Проверки

```sh
npm run lint
npm run build
node --experimental-transform-types --test qa/api-client.test.mjs
```

Последняя команда использует Node.js 24 и **явно тестовый** инъецируемый транспорт.
Приложение всегда обращается к HTTP API: автоматического mock fallback нет.
Результаты реальных HTTP-испытаний: `qa/api-smoke-result.json`, перечень браузерных
проверок и снимки: `qa/VERIFICATION.md`, `qa/screenshots/`.

`qa/api-smoke.py` принимает только localhost API с `allowFixtures=true`. Он
создаёт тестовый аккаунт, результат и проект в разрешённой отдельной тестовой БД.
Не запускать его на рабочем сервере. Runtime с httpx/Pillow:

```sh
TP_QA_API_URL=http://127.0.0.1:3000 PYTHONDONTWRITEBYTECODE=1 ../backend/.venv/bin/python qa/api-smoke.py
```

Тестовый API этой сессии — порт 8001, PostgreSQL — 55432. Конфигурация и
копия синтетического каталога в игнорируемой `.qa/`, хранилище результатов
также внутри frontend. Исходный backend и рабочая БД не изменялись.

## Фактическое поведение

- Аккаунт, проекты, история, названия и оценки получаются из API. LocalStorage
  не используется для авторизации или результатов.
- Генерация ждёт ответ сервера, поддерживает `done`, `queued`, `processing`.
  Процент показывается только если его прислал API.
- История сохраняется сервером автоматически. URL `?pattern=ID` повторно открывает
  серверный объект. Экспорт PNG/JPG — защищённый `/api/generations/ID/file`.
- Прекращение ожидания отменяет HTTP-запрос клиента, не обещает остановить сервер.
- v0 алгоритмический: текст сохраняется как заметка. Редактирование возвращает
  к параметрам; фиктивное AI-редактирование отсутствует.
- Синтетический каталог явно помечается предупреждением. Эскизы главной —
  декоративные SVG, не выдаются за результаты генерации или музейные материалы.

## Главная

Композиция: `src/components/home/HomePage.tsx`; оформление: `src/app/home.css`;
тексты: `src/content/home.ts`; SVG-эскизы: `src/components/home/Artwork.tsx`.
Главная предварительно рендерится в HTML, без прелоадера и кастомного курсора.
Логотипы в `public/logos/`; ссылки на официальные источники в `qa/VERIFICATION.md`.
Художественный финал утверждает владелец.

## Перед публикацией

1. Получить настоящий адрес/окружение, настроить `/api`, затем собрать frontend
   с нужным `API_ORIGIN`. Не переносить тестовую `.qa` и каталог fixtures.
2. Настроить HTTPS, Secure cookie и точный CORS origin на backend; проверить
   его health и timeout proxy для синхронной генерации.
3. Наполнить backend разрешёнными проверенными реальными мотивами и повторить
   браузерный путь на рабочем каталоге. Проверка на fixtures не подтверждает 100+.
4. Владелец предоставляет документы сервиса (условия/политику), их реальные URL
   и утверждает главную. Инертные названия несуществующих документов удалены
   из регистрации; интерфейс не утверждает, что пользователь прочитал их.
5. После назначения публичного URL добавить корректные canonical/Open Graph
   адреса и sitemap. Домен, контакты, доступы и юридические тексты не выдуманы.

Публикация не выполнена: адрес и инфраструктурные доступы не предоставлены.
