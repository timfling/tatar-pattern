# Как самостоятельно обновлять GitHub

## Через Терминал

Локальный репозиторий находится в папке `Разработка`:

```sh
cd "/Users/timfling/Desktop/Стартапы/ТАТАР ПАТТЕРН/Разработка"
git status
```

После изменения исходников:

```sh
git add .
git diff --cached --stat
git diff --cached
# Проверьте состав и содержимое изменений перед публикацией.
git commit -m "Краткое описание изменений"
git push origin main
```

`add` подготавливает изменения; `commit` сохраняет их локально; `push` отправляет
на GitHub. `.gitignore` исключает соседние папки и локальные данные.
Не используйте `git add -f` для .env, баз, датасетов или архивов.

Если работаете с нескольких компьютеров, перед редактированием выполните
`git pull --ff-only` при чистом `git status`. Если команда отказала из-за
расхождения истории, остановитесь и разберите изменения; не используйте force push.
При `nothing to commit` новых изменений нет. Удаления файлов тоже входят в `git add .`.

## Через GitHub Desktop

1. Установите GitHub Desktop и войдите в аккаунт timfling.
2. File → Add Local Repository → выберите эту папку `Разработка`.
3. После редактирования проверьте вкладку Changes и содержимое файлов.
4. Введите описание в Summary и нажмите Commit to main.
5. Нажмите Push origin.

На другом компьютере используйте Clone Repository. При HTTPS-аутентификации
используйте GitHub Desktop либо token/credential manager: обычный пароль GitHub
для Git не подходит. Токен не записывайте в URL origin или файлы проекта.

## Что обновляется

Публикуются `tatar-pattern` и исходники `ИИ`. Бизнес, summary, демки, датасет,
релизные архивы и локальные результаты исключены. Публикация на GitHub сама
по себе не обновляет работающий сайт — развёртывание выполняется отдельно.

Прежняя служебная история frontend сохранена локально в
`.local-git-backups/frontend.git`, вне публикации. Сейчас frontend входит
в общий репозиторий; команды Git выполняйте из `Разработка`.
